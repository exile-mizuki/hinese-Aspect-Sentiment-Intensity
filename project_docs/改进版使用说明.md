# 方面标记改进版使用说明

本次保留原实验，增加了目标方面标记、标签频率重加权的开发集对照，以及方面标记的三个随机种子实验。所有新结果在 results/refinement，不覆盖原指标。

## 直接演示

双击“改进演示.cmd”，等待模型加载。窗口出现“输入评论”后，输入一句话并回车，再输入方面词；多个方面用中文或英文逗号隔开。

示例：

```text
评论：土鸡超小盘，还有糖醋鱼外皮粉层炸太硬口感不好，但酱汁蛮好吃的。
方面：土鸡,酱汁
```

程序会并排显示原模型与选定模型的 V/A。可以连续输入多条评论；在“输入评论”处直接回车退出。原“运行演示.cmd”仍展示旧模型的固定例句。当前 test1 环境不需要增加依赖。

新入口加载开发集选中的方面标记单模型（种子 42、第 2 轮），在 CPU 上离线运行。它在原文中标记指定对象，标记处理已封装在程序中，用户直接输入普通文字即可。

## 汇报怎么说明

可以说：“我们在目标方面前后增加标记，使模型更容易区分同一句话的不同评价对象。开发集选定的新单模型在测试集上的 V-MAE 从 0.3160 降到 0.3030，同句方面 V 排序正确率从 81.14% 升到 84.75%。但 V-PCC 略有下降，强烈情绪子集也没有普遍改善，因此仍保留了失败案例。”

以下三个已归档的测试案例可用于对照讲解，完整评分在改进实验说明中：

- 服务态度与食物评价相反：R2103:S002，方面“服务态度”，新模型更接近人工分数。
- 长句评价多个对象：R2120:S005，方面“土鸡”，人工 V=4.00，原预测 6.55，新预测 3.94。
- 强烈不满：R0060:S023，方面“味道”，新模型仍出错，且两维平均误差比原模型更大。

模型平均预测也是对照实验：三份模型分别预测后等权平均，测试误差较低，但开发集未胜过选定单模型，所以没有依据测试分数替换演示方案。单模型结果、三种子运行均值和三模型集成分数是不同概念，汇报时不要混用。

## 查看和复核结果

- final_metrics.csv：原方案和标记方案，单模型与三模型平均，共四组开发/测试指标。
- per_seed_metrics.csv、seed_summary.csv：逐种子指标及三次运行的均值和样本标准差。
- slice_metrics.csv：多方面、极端 V、高 A、含否定字词等子集误差和样本数。
- aspect_order.csv：同句方面排序，包括打平数量。
- case_changes.csv：全部测试实例的人工分数、新旧预测和误差变化。
- metrics_comparison.png：四组测试指标图，可交给 PPT 负责人。
- 改进实验说明.md：训练、选模、结果及局限的完整说明。

在项目目录的 PowerShell 运行：

```powershell
& "C:\Users\lenovo\anaconda3\envs\test1\python.exe" src/report_refinement.py
```

该命令读取保存的预测，复核全部四组开发/测试指标并重建分析材料，不需要重新训练。原“复核技术成果.cmd”仍用于原六组实验；新旧分析各自保留。

## 复现训练与打包范围

训练源码为 src/refine_experiment.py，候选筛选记录为 candidate_selection.json，演示选模记录为 final_selection.json。若需要重训，请先在项目副本运行三个固定候选，再按开发集选中的方案补另两个种子。原预训练权重仍在课程设计的“模型缓存”目录中。

改进版压缩包包含旧模型及新演示模型、代码、预测、日志和图表。其他新实验检查点保存在本机 checkpoints/refinement 内；压缩包保留它们的预测与训练日志，重新训练或重新执行基于权重的 evaluate_refinement.py 时需要补齐这些检查点。报告复核命令不需要它们。

开发集只有 100 句，且旧测试集已用于此前错误分析，本次属于探索性改进。隐含评价与强烈情绪仍是局限，不能说已经全面解决。PPT 和真实成员贡献记录继续由小组整理后并入最终提交包。
