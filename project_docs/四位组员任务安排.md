# 四位组员任务安排

本安排面向五人小组，赵浩宇负责程序整合、现场演示和最终提交，其他四位组员分别负责数据、实验、案例和整套 PPT。组员暂按 A、B、C、D 标记，请在发给小组时替换成姓名。

进度更新：A、B、C 的技术材料及随机种子重复实验已由 AI 辅助完成，见《技术任务完成说明.md》。下文保留任务步骤，供组员复跑、核对和准备讲解；D 负责整合 PPT。《成员贡献记录.xlsx》按各人实际完成的工作填写。

项目为自然语言处理课程设计第 2 题“中文方面情感强度预测”。模型根据餐饮评论及指定方面词，输出愉悦度 V 和唤醒度 A，两项均为 1～9 分。当前已有六组实测结果，主改进方法为中文 BERT 方面句对模型。

项目目录为 E:/作业/自然语言处理/课程设计/中文方面情感强度预测。以下路径均从该目录开始。

## 组员 A · 数据检查和可视化

适合会基础 Python 或愿意练习 pandas 的同学。预计 2～3 小时。

**完成步骤**

1. 阅读 README 的数据部分和 src/main.py 中的 train、inputs 函数，说明一条训练实例由哪些字段构成。
2. 写一个可重复运行的数据检查脚本。先统计两份原始训练 JSON 的标注数，再统计同一句、同一方面合并后的实例数。对训练、开发、测试分别统计句子数、方面实例数、空文本数、NULL 方面数及非法或缺失标签数。开发和测试标签需与各自真值配对后统计。
3. 单独列出同句多方面的比例及训练、开发、测试之间重复的“文本＋方面”数量。遇到重复记录先报告来源和数量，遵循官方划分开展主实验。
4. 画训练集 V、A 分布图，并找一条同方面有多个意见的真实样本，演示如何取均值。把统计数和这一例子的文字说明交给组员 D，用于制作数据介绍页。

**交付物**

- 数据检查脚本、数据统计表、一张双面板分布图。
- 150～250 字的数据处理说明，交给组员 D 配合图表排版。

**验收**

训练集原始 8,523 条标注应合并为 7,476 个方面实例，来自 6,050 句。开发集为 100 句/115 方面，测试集为 2,000 句/2,658 方面。计数有差异时定位读取或分组原因。脚本须保留读取位置和分组规则，便于重跑。

**答辩准备**

能解释句子数与方面数为何不同、NULL 代表什么、同一方面多个意见为何取平均。

## 组员 B · 实验复核和结果图

适合会运行 Python、整理表格和画图的同学。基础任务预计 2～3 小时。

**完成步骤**

1. 在自己的项目副本中运行 src/compare_experiments.py，复核六组开发集和测试集成绩。该脚本读取已保存的预测，使用普通 CPU 即可。
2. 从 results/comparison/metrics.csv 中筛选测试集，画 V-MAE、V-PCC、A-MAE、A-PCC 四个子图。标清 MAE 越低越好、PCC 越高越好，保留六种方法。
3. 读取 results/bert_sentence/training_history.csv 和 results/bert_aspect/training_history.csv，画训练损失和开发集两维平均 MAE 随轮次的变化。
4. 整理整体对照和选模说明，连同图表源数据交给组员 D。说明两组 BERT 均选第 2 轮，依据是开发集平均 MAE 最低。
5. 写 200 字左右的结果分析。分别讨论从岭回归换到 BERT 的变化，以及保持 BERT 后增加方面输入的变化。

**交付物**

- 复核运行记录或截图、画图脚本、六组指标图、训练曲线图。
- 一段实验结果解释和图表源数据，交给组员 D。

**验收**

BERT 方面句对模型测试四指标应为 V-MAE 0.3160、V-PCC 0.9083、A-MAE 0.3250、A-PCC 0.7659。扩展到下一分句的模型四项总体测试指标均弱于原目标分句模型，图表应如实显示。

**有余力时补随机种子重复实验**

种子 42、17、2026 的两组 BERT 现已完成训练并汇总，可直接复核 `results/experiment_analysis/`。以下命令供需要重新训练时使用，建议在项目副本中执行。已有完整预训练权重保存在电脑的“模型缓存”中，随提交包的 demo_tokenizer 用于加载分词器和结构配置。

在项目目录的 PowerShell 中执行：

```powershell
$py = "C:\Users\lenovo\anaconda3\envs\test1\python.exe"
$base = "E:\作业\自然语言处理\课程设计\模型缓存\chinese-bert-wwm-ext"
foreach ($seed in 17, 2026) {
    & $py src/bert_experiment.py --model-path $base --mode both --device cuda --epochs 3 --batch-size 32 --max-length 80 --seed $seed --output-dir "results/repeats/seed_$seed" --checkpoint-dir "checkpoints/repeats/seed_$seed"
    if ($LASTEXITCODE -ne 0) { throw "种子 $seed 运行失败，请保存报错并检查。" }
}
```

种子 42 的结果位于 results/bert_sentence 和 results/bert_aspect，新增结果在 results/repeats/ 下。汇总三个种子的全部四指标及均值、标准差，报告是否每次都有相同的改善方向。每次均由开发集选检查点。该项额外需要使用已配好 GPU 环境的电脑，预计整理与操作再花 1～2 小时，实际训练时间以运行记录为准。

**答辩准备**

能说明 MAE 和 PCC 各表示什么，为什么第 3 轮训练损失更低却仍选第 2 轮，以及随机种子重复实验能检验什么。

## 组员 C · 典型错误与方面区分分析

适合文字分析较好、编程经验较少的同学。可用 Excel 或 WPS 打开 CSV，预计 2～3 小时。

**完成步骤**

1. 打开 results/comparison/dev_cases.csv 和 test_cases.csv。使用 Excel/WPS 时以 UTF-8 导入，避免中文乱码。
2. 将每个方面的绝对误差算为 |预测 V－true_V| 和 |预测 A－true_A|，逐条比较 improved、bert_sentence 和 bert_aspect 三种方法。
3. 整理 12 个“句子＋方面”案例，尽量来自不同评论。其中包括 4 个 BERT 有改善的案例、4 个 BERT 仍有明显误差的案例、4 个不同方面发生混淆或预测打平的案例。可覆盖否定、转折、跨分句、隐含方面或同句多对象，按实际遇到的现象命名。
4. 每例记录 ID、原句、方面词、人工 V/A、三种方法预测、误差，以及 1～2 句原因分析。人工评分以官方真值为准，自拟演示句只记录预测和语言现象。
5. 标出最适合展示的 3 个案例，包括成功和失败两种现象，并将原文、评分和简短解释交给组员 D。用 cases.csv 中的新案例补充已经展示过的蚵仔、牛肉例子。

**交付物**

- 一张 12 例案例表。
- 约 300 字的错误类型总结，以及推荐展示的 3 个案例，交给组员 D。

**验收**

每例能由 ID 和方面词回查到原始结果。文字分析引用具体词语或分句。模型内部关注了什么，只能作为推测；有了输入和输出可以直接验证的是分数和误差变化。

**答辩准备**

能指出例句中哪些词评价哪个方面，并解释为什么整体误差下降后，某些句子仍然会出错。

## 组员 D · 整套 PPT 制作与汇报编排

适合擅长 PowerPoint、排版和组织表达的同学。预计 3～4 小时，取决于收到材料的完整程度。

**完成步骤**

1. 打开现有《课程设计汇报-实验对照版.pptx》，阅读 README，理解任务、数据、六种方法及主要结果。
2. 先搭建汇报结构，依次包括任务定义、数据与处理、基线与 BERT 方法、实验设置、整体结果、方面区分、成功与失败案例、局限、成员分工及演示安排。以现有 10 页为起点，按教师规定的汇报时长调整。
3. 接收 A 的统计与分布图、B 的指标与训练曲线、C 的案例分析，把这些材料整合进同一份 PPT。统一字号、配色、图例、表格小数位和方法名称。
4. 每页用一句具体结论作标题，压缩大段文字。重点展示加入方面词后的变化、扩大窗口后指标下降，以及模型仍会出错的实例。
5. 将本组图表数字逐项核对到 B 提供的结果表，给数据来源、预训练模型和参赛对比注明来源。新增随机种子结果由 B 完成核验后再纳入。
6. 在备注栏写简短讲解提示，标明每页由谁讲、何时切换程序演示。向所有组员征集真实分工，完成成员页。
7. 全屏放映检查文字、图表和换页顺序，保存可编辑 PPTX 和 PDF 备用，并配合组长排练。

**交付物**

- 一份完整的最终汇报 PPTX 和对应 PDF。
- 各页讲解备注及讲述人员安排。

**验收**

整份 PPT 字体、图表和术语一致，正文在投影时可读。数字能追溯到实验文件，成员分工经本人确认。各组员能够用自己负责的页讲清工作内容。

**答辩准备**

负责开场的任务介绍和汇报衔接，能够说明为什么需要给同一句评论的不同方面分别评分。
